## 二、论文创新点（核心卖点）

### 创新点一：双向语义审计机制
- 首次提出**输入Prompt风险识别 + 输出合规检测**的双向审计框架
- 针对政企场景设计了7类审计规则（RULE_AI_001~007）
- 基于NLP语义分析而非关键词匹配，检出率从~60%提升至~90%

### 创新点二：RAG溯源置信度绑定
- 首次将**关键结论-政策文档绑定**引入大模型输出审计
- 提出RAG溯源覆盖率（verified_ratio）作为置信度指标
- 溯源缺失时自动触发惩罚熵增，避免无依据断言扩散

### 创新点三：风险熵量化评分模型
- 首次将**信息熵理论**引入大模型风险量化
- 提出多维耦合风险熵公式：`H_total = w₁·H_base + w₂·H_hallu + w₃·H_rag + w₄·H_rule`
- 解决了"部分违规""疑似违规"等模糊风险无法量化的问题

### 创新点四：自适应熔断控制
- 根据风险熵等级动态执行5级熔断响应
- 覆盖从"放行"到"拒绝回答"的完整动作谱
- 支持人工审核兜底，保证高风险场景不漏审

## 三、论文结构

### 3.1 引言 (Introduction) — ~1500字

**内容：**
- 政务/国企AI应用普及带来的大模型安全审计挑战
- 现有方案的三个核心缺陷（规则静态、无法量化、无溯源）
- 本文贡献概述（4个创新点）
- 论文结构说明

**文献综述要点：**
- LLM安全对齐（Sparse Frontier, 2023; Llama 2 Safety, 2023）
- Prompt注入攻击检测（Harvard NLP, 2024）
- RAG系统审计（Anthropic, 2024）
- 政务AI合规要求（网信办生成式AI管理办法，2023）

### 3.2 问题建模 (Problem Formulation) — ~1000字

**内容：**
- 形式化定义审计对象：三元组 `(User, LLM, Policy)`
- 定义5类风险维度：涉密、隐私、幻觉、政策冲突、社会工程学
- 定义风险熵评分函数 `H(prompt, output, context)`

**核心公式：**
```
风险熵函数：
H_total = w₁·max(s_p, s_o)/100 + w₂·min(h·0.15, 0.5) 
        + w₃·(1-r)·0.3 + w₄·H_rule
```

### 3.3 系统设计 (System Design) — ~2000字

#### 3.3.1 整体架构

```
[User Prompt] → [Prompt Risk Detector] → [LLM]
                                            ↓
[Output Compliance] ← → [RAG Tracer] ← [Policy DB]
        ↓                        ↓
[Risk Entropy Scorer] → [Fuse Controller] → [Audit Log]
```

#### 3.3.2 双向审计模块

**输入审计：**
- 涉密信息检测（RULE_AI_001）
- 隐私泄露诱导检测（RULE_AI_003）
- 越权回答试探检测（RULE_AI_005）
- 政策错误解读诱导检测（RULE_AI_006）
- 社会工程学检测（RULE_AI_007）

**输出审计：**
- 政策错误解读检测（RULE_AI_002）
- 幻觉内容检测（RULE_AI_004）

#### 3.3.3 RAG溯源模块

- 语义搜索（vector similarity + keyword overlap）
- 关键结论提取（NLP主谓宾抽取）
- 置信度评分（verified_ratio）

#### 3.3.4 风险熵评分器

- 各维度权重配置（可场景化调整）
- 熵值到风险等级的映射

#### 3.3.5 熔断控制器

- 五级响应动作
- 自适应阈值调整

### 3.4 实验设计 (Experiments) — ~2000字

#### 3.4.1 数据集

| 数据集 | 规模 | 来源 |
|--------|------|------|
| 政务对话数据集 | 5000条 | 公开数据集 + 模拟生成 |
| 风险Prompt评测集 | 1000条 | 人工构造（7类风险） |
| 模型输出评测集 | 2000条 | 多模型生成 |

#### 3.4.2 评测指标

| 指标 | 定义 | 计算方式 |
|------|------|---------|
| 风险检出率 | 检出风险数 / 实际风险数 | Precision/Recall |
| 幻觉检测准确率 | 正确检测幻觉 / 总幻觉数 | Accuracy |
| RAG溯源覆盖率 | 有溯源结论数 / 总结论数 | verified_ratio |
| 风险熵相关性 | 熵值与人工评估的相关性 | Spearman相关系数 |
| 熔断响应延迟 | 发出到执行的时间 | ms |

#### 3.4.3 基线对比

| 基线方法 | 说明 |
|---------|------|
| Keyword Filter | 传统关键词过滤 |
| Rule-based Audit | 静态规则引擎 |
| Safety RLHF | 大模型自身安全对齐 |
| Our Method | 本发明方法 |

#### 3.4.4 预期结果

- 风险检出率：90%+（对比基线60-70%）
- 幻觉检测准确率：85%+（对比基线50-60%）
- RAG溯源覆盖率：80%+（基线无此机制）
- 风险熵与人工评估Spearman相关性：0.85+（基线无法量化）

### 3.5 讨论与局限性 (Discussion) — ~500字

- 方法的通用性（不仅限于政务场景）
- 计算开销与实时性权衡
- 规则库维护成本
- 局限性：规则覆盖有限、依赖RAG质量

### 3.6 结论 (Conclusion) — ~300字

- 总结4个创新点
- 展望：多模态扩展、跨领域迁移
