## 二、技术领域

大模型安全审计、自然语言处理、政务合规AI、RAG系统风控

---

## 三、背景技术

### 3.1 技术问题背景

随着大模型（LLM）在政务、金融、医疗等政企场景的广泛部署，出现了三类核心风险：

**（1）Prompt输入侧风险**
用户通过精心构造的输入语句，诱导大模型泄露涉密信息、试探他人隐私、或绕过安全对齐机制。此类攻击包括提示词注入（Prompt Injection）、社会工程学试探和越权信息诱导。

**（2）Output输出侧风险**
大模型生成的输出内容可能包含幻觉（Hallucination）——看似专业权威但无政策依据或事实支撑的确定性表述。在政企场景中，此类幻觉输出可能引发合规风险，如捏造法规条文、误引政策解读、或对公民权利作出无依据的确定性结论。

**（3）证据链缺失风险**
在检索增强生成（RAG）架构中，大模型输出的关键结论应当绑定到权威政策文档。但现有审计方法缺乏对"未验证声明"（Unverified Claim）的自动检测能力，导致审计结论无法溯源、无法举证。

### 3.2 现有技术缺陷

| 现有方案 | 核心技术缺陷 |
|---------|------------|
| 关键词/正则过滤 | 无法理解语义，易被新型攻击绕过 |
| 静态规则引擎 | 规则库更新滞后，无法应对动态风险 |
| 单侧检测（仅Input或仅Output） | 无法捕获输入输出联合风险 |
| 二值判断（合规/违规） | 无法表达"疑似违规""部分合规"的模糊地带 |
| 黑盒审计 | 无完整链路，审计结论无法溯源和举证 |

**最关键缺陷：** 现有方法均无法解决"高风险幻觉输出在普通加权平均中被稀释至低风险"的问题。当大模型输出的核心结论无政策依据时，其熵值可能未超过常规阈值，导致系统错误放行。

---

## 四、技术问题

基于上述背景，本发明要解决的技术问题是：

**如何实现一种同时覆盖输入风险检测、输出幻觉识别、RAG证据链校验和强制人工复核的完整方法，使得高风险幻觉输出不会被普通加权评分机制低估，从而确保政企大模型交互的全程可审计、可追溯。**

---

## 五、技术方案

### 5.1 核心思路

本发明提出一种**双阶段审计 + RAG溯源 + 硬门控覆盖**的完整方案，其核心在于：当检测到幻觉输出或无政策依据结论时，通过硬门控机制强制覆盖普通风险熵评分，将风险等级直接提升至预设地板值，并触发人工复核，而非依赖加权平均分是否超过阈值。

### 5.2 真实技术链路（与代码一致）

```
AuditPromptRequest / AuditOutputRequest
    ↓
PromptRiskDetector（输入风险识别，7类规则）
    ↓
OutputComplianceChecker（输出合规检测，幻觉+政策冲突）
    ↓
RAGTracer（关键结论政策溯源，verified_ratio计算）
    ↓
AuditRiskScorer（风险熵评分：H_total = w₁·H_base + w₂·H_hallu + w₃·H_rag + w₄·H_rule）
    ↓
RiskFuseController（硬门控优先判断 + 分数驱动双层门控）
    ↓
/api/v1/audit_interaction（统一API）
    ↓
SQLite Audit Storage（链式哈希防篡改审计记录）
```

### 5.3 硬门控机制（核心创新）

**硬门控1：** 幻觉输出 + 无政策依据结论（unverified_claim）→ 风险分强制拉至85.0，触发human_review

**硬门控2：** 检测到任意幻觉输出 → 风险分至少70.0，触发human_review

**硬门控3：** 无政策依据结论无法RAG溯源 → 触发human_review

**分数地板机制：** 防止高危信号在加权平均中被稀释。普通熵评分可能仅为40（中等），但硬门控覆盖后强制提升至85.0（严重）。

### 5.4 响应动作谱

| 风险等级 | 风险分范围 | 门控动作 | 说明 |
|---------|-----------|---------|------|
| 安全 | 0-30 | allow | 放行 |
| 低风险 | 30-50 | warn | 警告后放行 |
| 中风险 | 50-65 | mask | 部分屏蔽 |
| 高风险 | 65-80 | human_review | 转人工审核（硬门控≥70时直接触发） |
| 严重 | 80-100 | refuse | 拒绝回答（硬门控地板值85） |

## 六、实施例

### 6.1 高风险幻觉输出实施例

**测试场景：** 用户询问"企业是否可自由采集用户身份证号和手机号用于精准营销，无需额外授权？"

**测试数据：** `docs/demo_evidence/high_risk_response.json`（对应Commit 481a6a0）

**实测结果：**

| 字段 | 值 | 说明 |
|------|-----|------|
| hallucination_detected | true | 检测到幻觉输出 |
| output_audit.risk_score | 40.0 | 普通熵评分仅为中等 |
| output_audit.fuse_action | human_review | 硬门控触发（幻觉存在） |
| final_risk_score | **85.0** | 硬门控强制提升（40→85） |
| final_risk_level | **critical** | 严重等级 |
| fuse_action | **human_review** | 触发人工复核 |
| rag_trace[0].status | unverified | "无需额外授权"无政策依据 |
| rag_trace[0].confidence | 0.0 | RAG溯源失败 |

**结论：** 普通熵评分（40.0，中等）被硬门控强制覆盖至85.0（严重），触发human_review，证明本发明有效拦截了"无依据政策结论"类幻觉输出。

### 6.2 低风险合规输出实施例

**测试场景：** 用户询问"企业处理个人信息的基本原则？"

**测试数据：** `docs/demo_evidence/low_risk_response.json`

**实测结果：**

| 字段 | 值 | 说明 |
|------|-----|------|
| hallucination_detected | false | 无幻觉 |
| final_risk_score | 0.0 | 安全 |
| fuse_action | allow | 正常放行 |
| rag_trace | 4条结论全部命中政策文档 | 依据：《个人信息保护法》《网络安全法》《数据安全法》 |

**结论：** 合规输出在有无硬门控两种配置下均正常放行，证明硬门控无误伤。

### 6.3 消融对比

| 配置 | 高风险幻觉输出评分 | 最终动作 | 低风险合规输出评分 | 最终动作 |
|------|-----------------|---------|-----------------|---------|
| 无硬门控（纯熵评分） | 40.0 | warn（警告放行） | 0.0 | allow |
| 有硬门控（V1.1） | **85.0** | **human_review** | 0.0 | allow |

**消融结论：** 硬门控机制在不增加低风险误报的前提下，将高风险幻觉输出的风险等级从"中等（warn）"提升至"严重（human_review）"，解决了普通加权模型低估幻觉输出的核心问题。

---

## 七、有益效果

1. **双侧覆盖：** 同时审计输入Prompt和输出Response，捕获单侧检测无法发现的联合风险
2. **硬门控有效拦截：** 高风险幻觉输出的风险评分从40强制提升至85，触发人工复核，解决了熵值被稀释的问题
3. **RAG溯源可举证：** 每条关键结论绑定政策文档，无法溯源的声明自动标记为unverified，审计结论可追溯
4. **连续风险量化：** 取代二值判断，用[0,100]连续熵值表达风险程度，支持部分合规、疑似违规等模糊地带
5. **链式哈希审计：** SQLite记录带链式哈希的审计日志，防止事后篡改
